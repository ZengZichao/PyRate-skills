# `assets/files/` - provenance and runnability index of the 77 shared fixtures

Every file listed here exists on disk; the list was taken with
`ls -1 assets/files | grep -v '^README.md$'` (77 names) and each row's numbers were
re-measured on the shipped file with `wc -l`, `wc -c` and
`grep -vc -E '^\s*(#|rem |@echo|//|$)'` (data rows), never copied from an authoring
report. One row per file, no row for a file that is not there.

Fixtures are **suite-level**: a skill reaches them as `../assets/files/<name>`, so the
whole suite has to be installed together for the paths to resolve (see
`../../README.md`, section 四).

**What `status` means.** `scripts/audit_corpus.py` check Q accepts a fixture in one of two
ways: either its stripped body is found byte-exact inside some mirror, or a row of this
index - naming the file on the same line - says how it deviates. Every fixture here carries
a provenance header of ours, so **0 of 77 pass the byte-exact branch**; all 77 are declared
below. The vocabulary:

- **verbatim** - the payload is a byte-identical span of the named mirror. Only the
  provenance header is ours, so the file *as shipped* is not byte-verbatim.
- **derived** - reformatted (markdown pipe table re-tabulated to tab-separated text,
  backticks / padding / `...` rows dropped), reordered, excerpted, projected, or annotated
  with our own tags. Values are the mirror's unless the row says otherwise.
- **synthesized** - a worked example this suite constructed, or a helper/output of our own.
  Its *role and shape* are documented at the cited mirror line; the numbers, names and code
  are ours. Nothing in this directory was fetched from the upstream repository's
  `example_files/`: this corpus does not mirror that directory and never made it readable
  here, so no fixture may be described as a copy of it. Where a file name or a SKILL.md row
  says `upstream`, the file's own header retracts the claim - see "Disagreements" below.

Line numbers in the `copied from` column are **mirror** lines
(`<skill>/references/<file>.md:LINE`, 8-line frontmatter included). The mirrors' own headers
sometimes print the corpus numbering; corpus line = mirror line - 8.

## Disagreements with the SKILL.md tables

The rows above follow **the file**, not the prose. Eight claims made by a SKILL.md do not
hold against the shipped file; each was measured on disk. They are reported here because the
files must not be edited by this pass.

- **D1 - `cmdref-epochs_q.txt` row count.** `pyrate-command-reference/SKILL.md:398` says
  "31 epoch-boundary ages". The file has **32** numeric rows
  (`grep -vc -E '^\s*(#|$)' assets/files/cmdref-epochs_q.txt` = 32). Its own header says
  "SYNTHETIC". The 0.0117-541.0 range in that row is right; the count is off by one.
- **D2 - upstream provenance of the epoch files.** `pyrate-command-reference/SKILL.md:398-399`
  label `cmdref-epochs_q.txt` and `cmdref-epochs.txt` `verbatim` copies of
  `dsilvestro/PyRate example_files/epochs_q.txt` / `epochs.txt`, and `cmdref-epochs.txt`
  "30 fixed shift ages". Both files declare `values SYNTHETIC` in their headers, and
  `cmdref-epochs.txt` holds **31** rows. The corpus never contains those `example_files/`,
  so no verbatim copy of them can have been made here.
- **D3 - upstream provenance of the `-d` / `-trait_file` tables.**
  `pyrate-command-reference/SKILL.md:396` (`cmdref-SE-table.txt` … "verbatim" from
  `Ursidae_SE.txt`, header words called "upstream example-file convention"), `:397`
  (`cmdref-SE-table-multi-replicate-EXCERPT.txt` "the first four columns are verbatim") and
  `:400` plus `pyrate-summarize-results/SKILL.md:151` and `pyrate-trait-age-models/SKILL.md:45`
  (`cmdref-trait-table.txt` "downloaded … as", "extracted verbatim from upstream
  `example_files/Ursidae_SE.txt`") all assert upstream copies. All three files carry
  `values SYNTHETIC` headers that explicitly retract the earlier verbatim / row-count /
  byte-identity / md5 claims. Their row counts do match (76 non-comment lines = header +
  75 rows), and the numbers `pyrate-trait-age-models/SKILL.md:45` quotes from
  `cmdref-trait-table.txt` are really on its lines 4, 7 and 71 - only the provenance is wrong.
- **D4 - the four `occ-*-upstream-*` / `EXCERPT` names.**
  `pyrate-input-file/SKILL.md:470-472, 483, 485, 486` describes
  `occ-pyrate-input-structure-EXCERPT.py`, `occ-taxonlist-upstream-EXAMPLE.txt`,
  `occ-check-names-input-upstream-EXCERPT.txt` and `occ-ursidae-upstream.txt` as
  "upstream-derived files … from the upstream `example_files/`". Each header says the
  opposite: `synthesized by this suite`, and for two of them literally
  "'upstream' … is NOT a provenance claim". The index rows say `synthesized`.
- **D5 - `occ-ursidae-upstream.txt` line endings and md5.**
  `pyrate-input-file/SKILL.md:484` asserts byte-verbatim upstream, md5
  `cbea033159a13ea4d5311b7a8372def3`, "CR line endings" and a "965-occurrence table".
  Measured on the shipped file: `wc -l` = 977, data rows = 966, `tr -cd '\r' | wc -c` = **0**
  (no CR bytes at all), and `md5sum` = `998074de99f2729da7b34a412f58e025`.
- **D6 - `pres-epochs_q.txt` is described as byte-clean.**
  `pyrate-preservation-models/SKILL.md:235` says the file is "that linked upstream example
  file … kept **byte-clean** (no comment header) because PyRate parses it". The file opens
  with a 6-line `# provenance: synthesized by this suite` header and is 661 bytes
  (`wc -c`), against 1316 bytes for the headerless-numbered `cmdref-epochs_q.txt`; the two
  age lists are otherwise `diff`-identical. A byte-clean claim also hides a real risk the
  corpus does not settle: whether `PyRate.py -qShift` tolerates leading `#` comment lines.
- **D7 - no fixtures section in `pyrate-mcmc-tuning/SKILL.md`.** The other 13 skills carry a
  `## Runnable fixtures` H2; `pyrate-mcmc-tuning` lists its four `tuning-` fixtures inside the
  Resources table instead, so a reader looking for the contract's section finds none.
- **D8 - `tuning-term-frequency-audit.sh` usage line.** Its header says it "runs from
  anywhere", which holds for a path containing a directory component but not for
  `sh tuning-term-frequency-audit.sh` invoked from inside `assets/files/`: `${0%/*}` then
  leaves `$0` unchanged, `cd` resolves one level too shallow and the script exits 1 with
  `cannot find …/assets/pyrate-mcmc-tuning/references` (reproduced 2026-11-20). Use
  `sh ./tuning-term-frequency-audit.sh`.
