# `PyRateContinuous.py`: rates as functions of time-continuous covariates

## Overview

`PyRateContinuous.py` implements "birth-death models in which rates vary through time through linear or exponential correlations with a time-continuous variable" (`references/tutorial-2.md`:92). `../pyrate/references/home.md`:40 introduces the same program with near-identical but **not byte-identical** wording — "a birth-death model in which rates vary through time through linear or exponential correlations with a time continuous variable" (singular *model*, and *time continuous* without the hyphen) — and cites Silvestro D., Antonelli A., Salamin N., Quental T. B. (2015) The role of clade competition in the diversification of North American canids. PNAS, 112, 8684-8689 (`../pyrate/references/home.md`:42), whose equation 7 is the reference for the exponential correlation `-m 0` (`references/pyratecontinuous.md`:37). The variable is either the clade's own sampled (range-through) diversity, run with `-DD` (`references/tutorial-2.md`:100), or an external time series such as paleo-temperature or sea level supplied with `-c` (`references/pyratecontinuous.md`:32, `references/tutorial-2.md`:92,128). The program "does not model preservation and assumes that the times of origination and extinction of each lineage are known or have been estimated, typically in a previous PyRate analysis" (`references/pyratecontinuous.md`:10), so its input is the 4-column `_se_est.txt` table produced by `-ginput`, not a fossil occurrence file.

The riskiest assumption this skill removes: **`-ginput` writes mean posterior times ("Mean posterior times of origination and extinction are calculated from each log file", `references/pyratecontinuous.md`:14), and a `-ginput` run without `-resample` throws the uncertainty of those times away before the correlation is estimated** (`references/tutorial-2.md`:26-31 section heading "Mean times of origination and extinction" vs `:52-57`, "To extract multiple samples of the times of origination and extinction from the posterior instead of the mean"). Everything downstream (`Gl`, `Gm`, marginal likelihoods) is conditioned on those point estimates. Second risk: the documents disagree about which executable takes `-ginput`, and the PyRate wiki command list assigns a different meaning to both `-mL` and `-r` (see the hazard table, *Flag-collision warning* and *Not documented in this wiki*).

(1) The combine-replicates output is called `...se_ext.txt` at `references/tutorial-2.md`:45,49,66 while every command uses `..._se_est.txt` (`:68,74,79,86,102,106,122,132`). Reconciling the two documents on "4 columns": `references/pyratecontinuous.md`:11 fixes columns 3 and 4 as origin and extinction, while `references/tutorial-2.md`:24 says "Finally the following columns contain the time of origin and extinction of each species or taxon" — i.e. the tutorial's phrasing already allows the replicate columns that `-tag`/`-resample` add. Read the four-column rule as four columns *per estimate*. The `-c` table's column **order** and its header **labels** are printed nowhere for PyRateContinuous. Two sibling programs print the analogous table: MBD "two columns for time before present and predictor values" under the header `time | predictor` with times ascending from `0` (`../pyrate-diversity-dependence/references/tutorial-4.md`:54-62), and covariate-DES prints `| age | sealevel |` with ages ascending from `0.000` (`../pyrate-des/references/tutorial-5.md`:240-247). Both are consistent with `references/tutorial-2.md`:136 ("shifted to equal 0 at the present"), and `../assets/files/cont-temperature-EXCERPT.txt` follows that precedent — header labels and all — but it is **derived**, not a copy: no PyRateContinuous covariate file is reproduced anywhere in this corpus.

**Flag-collision warning (documented conflict inside this corpus).** On the *PyRate* command list, `-mL` "Set the number of speciation rates through time used in the MCMC" (`../pyrate-command-reference/references/command-list.md`:111-113) and `-r` "Set the number of parallel 'heated' chains for Metropolis Coupled MCMC (MC3) analysis" (`../pyrate-command-reference/references/command-list.md`:193-195). Neither page mentions PyRateContinuous. So `-mL <directory>` (marginal likelihoods) and `-r <rescaling>` as used in Tutorial 2 carry **different meanings in the only "detailed command list" this corpus has**; the per-program reading above is the one the PyRateContinuous examples support, and no mirror reconciles them.

## Diversity-dependent birth-death models (Tutorial 2 route)

`-DD` needs no extra file: diversity is the clade's own range-through diversity derived from the input table (`references/tutorial-2.md`:100). "the program implements two models of of diversity dependence defined by the flag `-m`" (`:104`, doubled "of" as printed): exponential `-m 0` and linear `-m 1`; `-m -1` is the constant-rate, diversity-independent null model "For the purpose of model testing" (`:108`). Budget `100,000`-`1,000,000` iterations because "PyRateContinuous does not estimate times of origination and extinction nor preservation rates" (`:112`).

Scope boundaries inside diversity dependence: this skill covers **single-clade** DD via `-DD`. Multi-clade DD (`PyRateMCDD.py`, and the multivariate birth-death `PyRateMBD.py` that models several time-continuous variables at once) is owned by `pyrate-diversity-dependence` (`../pyrate-diversity-dependence/references/tutorial-4.md`:24-42,44-68); note that MCDD's input table is the very same 4-column `-ginput` output with the clade column populated (`:24,28`), and that MBD predictors are separate files in a directory (`:53-64`).

## Correlation with an external time-continuous variable (`-c`)

The tutorial's own section "Correlation with a time-continuous variable" (`references/tutorial-2.md`:127) covers what the wiki page covers under `-c` (`references/pyratecontinuous.md`:31-32), with two additions worth keeping straight:

- **The model.** "You can fit birth-death models where the speciation and extinction rates are changing through time as a linear or exponential function of a time-continuous variable, such as a proxy for paleo-temperature" (`references/tutorial-2.md`:128); as under `-DD`, `-m 0` is the default **exponential model** and `-m 1` the **linear model** (`references/tutorial-2.md`:134, `references/pyratecontinuous.md`:34-38). `-c` is an *alternative to* `-DD`, never an addition to it (`references/pyratecontinuous.md`:32, hazard 7).
- **The extra file.** Exactly one: a covariate table, "a simple tab-separated text file with a header (first row) and two columns indicating times and variable values (an example is provided in `PyRate-master/example_files/temperature.txt`)" (`references/tutorial-2.md`:128) — the wiki words the columns as "the time of change and the value of the variable" (`references/pyratecontinuous.md`:32). Pass it as the argument of `-c`; the printed call is `python PyRateContinuous.py -d .../Canidae_1_G_se_est.txt -m 0 -c temperature.txt` (`references/tutorial-2.md`:132).
- **Rescaling decides what the coefficient means.** "The time-continuous variable is by default rescaled so that its range of values equals 1. It is additionally shifted to equal 0 at the present" and "The rescaling of the time-continuous variable can be changed using the flag `-r`" (`references/tutorial-2.md`:136`). No argument form, example or unit for `-r` is printed anywhere (see *Not documented in this wiki*).
- **The logged parameters are the same names as under `-DD`.** "*Gl* and *Gm* for speciation and extinction, respectively, and the **baseline speciation and extinction rates** (indicated by *L0* and *M0* in the log file)" (`references/tutorial-2.md`:136; the wiki logs them for `-c` runs too, `references/pyratecontinuous.md`:32) — read them against 0 with the 95% HPD rule of `references/tutorial-2.md`:115.
- **Plotting.** `-plot` works the same for a `-c` run: `python PyRateContinuous.py -d .../Canidae_1_G_se_est.txt -m 0 -c temperature.txt -plot .../my_logfile.log -b 100` (`references/tutorial-2.md`:138-140).
- **One variable at a time.** No doc gives `-c` more than one file; several simultaneous correlates are the MBD model (`-var <directory>`) routed to `pyrate-diversity-dependence`, and environmental predictors inside a two-area dispersal model are DES `-varD`/`-varE`, routed to `pyrate-des`.

## Model testing with thermodynamic integration

1. Enable TI with `-A 1` on the model, exactly as the analysis would be set up: "The analysis setup and model specification are the same described above and the TI algorithm is enabled by the flag" (`references/tutorial-2.md`:147 — the source prints two spaces before the `-A 1` that closes that sentence) and the example at `:149`. 10 scaling categories by default; `-n` is per category (`:151`); PyRate saves a ‘*_marginal_likelihood.txt*’ file under `-A 1` for its own runs (`../pyrate-command-reference/references/command-list.md`:49). If the ~10x iteration cost of hazard 5 is the problem, the corpus prints exactly two knobs: `-k` = "Number of scaling factors used for marginal likelihood estimation in TI ... used only when running TI analysis (i.e. with `-A 1`)", "`-k 10` (default)", and `-a` = "Shape parameter of the beta distributed scaling factors in TI analyses", "`-a 0.3` (default)" (`../pyrate-command-reference/references/command-list.md`:205-211). Both are printed on the *PyRate* page, so applying them to `PyRateContinuous.py` is **inferred**; raising `-k` buys accuracy at more compute (`:206`), and lowering it is the only documented way to shrink the 10 categories of `references/tutorial-2.md`:151.
2. Run one TI analysis per competing model. The comparisons the docs name are "diversity-dependent models with linear vs exponential correlation" and "diversity-dependent models with that of temperature-dependent models" (`references/tutorial-2.md`:147) — the printed `-A 1` example is a `-c` run (`:149`); **no `-DD ... -A 1` line is printed**, so building one is by inference from `:102-108` + `:147`.
3. Collect them in one directory and run `-mL <path> -b <burnin>`; `-mL` takes the directory and processes "each file in the directory with extension ".log"" (`references/tutorial-2.md`:153-155). `-b` is mandatory in spirit here (`:153`, hazard 4). **The directory must hold nothing else with a `.log` extension** (hazard 12): a `-DD`/`-c` parameter-estimation log such as the `..._DD_0_exp.log` at `references/tutorial-2.md`:122 is indistinguishable from a TI log by extension, so `-mL` integrates it too and its number lands in the same table. Keep the TI runs in a directory of their own, or `mv` the finished TI logs into an empty directory before step 3 — an **inferred** remedy, since no page pairs `PyRateContinuous.py` with `-wd` and none names the files it writes. Tag each run with `-out TI_<model>` (`../pyrate-command-reference/references/command-list.md`:32-33, documented for PyRate as the way "to avoid overwriting output files when running several instances of the same analysis") so the runs do not overwrite one another while sharing a directory; the PyRateContinuous filename rule is **not documented**, so verify the tags appear before trusting them.
4. Read the single text file of marginal likelihoods and the new cold-chain logs, which are usable for parameter estimation in Tracer (`references/tutorial-2.md`:157).

**The arithmetic the docs do not perform:** Tutorial 2 never subtracts, ratios, or thresholds the marginal likelihoods, never names a decision rule, and never shows a second `-A 1` command next to the first. Bayes factors are documented **only** for PyRate, by `-BF`, which "Takes the marginal likelihoods calculated under two birth-death models (from ‘*_marginal_likelihood.txt’ files) to calculate Bayes Factors" (`../pyrate-summarize-results/references/summarize-results.md`:68) — the threshold categories and the whole comparison machinery are owned by `pyrate-summarize-results`; load that skill for them. Whether `-BF` can read the PyRateContinuous `-mL` text file is not stated anywhere in this corpus (see *Not documented in this wiki*).

## Worked example

Only the fixtures in `../assets/files/` and the command lines the docs print. The grouping into one sequence (and the `-n`/`-s` values inside the documented `100,000`-`1,000,000` range) is by inference; each flag is documented individually above.

```sh
# Prerequisites: PyRate release dir containing PyRate.py, PyRateContinuous.py AND the
# folder pyrate_lib (../pyrate/references/home.md:39,61). Interpreter: the corpus contradicts
# itself, so do not report a settled version — Home pins "Python 2.6 – 2.7" and bans 3.x
# (../pyrate/references/home.md:69) while the install tutorial opens with Python 3.10+ required
# (../pyrate-installation/references/virtual-environment.md:13); pyrate-installation owns that
# conflict. numpy+scipy (../pyrate/references/home.md:71) and the RScript
# shell command for -plot (../pyrate/references/home.md:84) are stated on the Home page alone.
FIX=$(cd ../assets/files && pwd)     # absolute path to this suite's fixtures, resolved BEFORE the cd
cd /path/to/PyRate-master            # your PyRate release directory

# 0. (optional) build the input table from a previous PyRate run. The docs disagree about
#    the program: the tutorials run it through PyRate.py (references/tutorial-2.md:29 and
#    ../pyrate-bdnn/references/tutorial-bdnn.md:477) while the wiki page runs it through
#    PyRateContinuous.py (references/pyratecontinuous.md:16,18) and -ginput has no entry
#    at all in the PyRate command list. Following the two tutorials here:
python PyRate.py -ginput /path/to/Canidae_1_G_mcmc.log -b 100        # -> Canidae_1_G_se_est.txt; the -b is mandatory in practice (hazard 11) and the value the docs print (tutorial-2.md:29)
cp $FIX/cont-se-est.txt ./Canidae_1_G_se_est.txt                     # fixture stands in for it
cp $FIX/cont-temperature-EXCERPT.txt ./temperature.txt               # fixture stands in for example_files/temperature.txt

# 1. diversity dependence, exponential (the documented default; references/tutorial-2.md:102,106)
python PyRateContinuous.py -d ./Canidae_1_G_se_est.txt -DD -m 0 -n 1000000 -s 1000

# 2. linear DD, and the constant-rate null model needed for comparison (tutorial-2.md:104,108)
python PyRateContinuous.py -d ./Canidae_1_G_se_est.txt -DD -m 1 -n 1000000 -s 1000
python PyRateContinuous.py -d ./Canidae_1_G_se_est.txt -DD -m -1 -n 1000000 -s 1000

# 3. correlation with an external time-continuous variable (tutorial-2.md:132), linear model
python PyRateContinuous.py -d ./Canidae_1_G_se_est.txt -m 1 -c ./temperature.txt -n 1000000 -s 1000

# 4. rate curves: -plot reads a PyRateContinuous log, -b is the plotting burn-in in SAMPLES
#    ("The command `-b 200` specifies that the first 200 samples are discarded as burnin",
#     tutorial-2.md:124) — the value below is the one this exact command is printed with
LOG=$(ls -t ./*se_est*.log | head -1); echo "plotting $LOG"
python PyRateContinuous.py -d ./Canidae_1_G_se_est.txt -m 1 -c ./temperature.txt -plot "$LOG" -b 100   # -b 100 verbatim from tutorial-2.md:140; a bigger number is not safer - under the samples reading of hazard 10 it eats the logged chain

# 5. model testing: TI per model, each into its own directory, then marginal likelihoods (tutorial-2.md:149,155).
#    Keep -c/-DD/-m identical to the runs you want to compare. -A 1 runs 10 scaling
#    categories by default (tutorial-2.md:151); the ~10x cost is inference, not a doc statement.
#    Do NOT expect to separate these runs with a flag: PyRateContinuous.py is never documented with a
#    `-wd` (that is a PyRate.py option, ../pyrate-bd-analysis/references/command-list.md:22, and a
#    PyRateDES.py one, ../pyrate-des/references/tutorial-5.md:69), and `-out` appears 0 times on either
#    of its two pages - it is printed for PyRate.py ("Add tag to default stem name of output files ...
#    useful to avoid overwriting output files when running several instances of the same analysis",
#    ../pyrate-bd-analysis/references/command-list.md:32-33) and all four command lines in the corpus that
#    use it run PyRate.py (../pyrate-bdnn/references/tutorial-bdnn.md:208, :249, :397, :415). Neither flag
#    can therefore be carried over here; what filenames TI writes is not stated on any page (`undocumented`)
#    beyond "Running TI produces a single log file as output" (references/tutorial-2.md:151). Separate the
#    three runs in the shell instead: `mkdir -p` one directory per model, `cd` into it, run there, and move
#    that run's logs out before the next iteration starts. Because no `-out` tag is available, the moves
#    MUST stay inside the loop - moving everything after the loop would hand `-mL` only the last run's log.
mkdir -p ./TI_logs        # -mL integrates EVERY ".log" in the directory it is given
                          # (references/tutorial-2.md:153 - hazard 12): this directory must end up holding
                          # exactly the three TI logs, or the steps 1-3 logs (e.g. ..._DD_0_exp.log,
                          # tutorial-2.md:122) get marginal likelihoods too.
for M in -1 0 1; do
  mkdir -p ./TI_$M                                    # must precede the cd, which cannot create it
  ( cd ./TI_$M && python ../PyRateContinuous.py -d ../Canidae_1_G_se_est.txt -m $M \
        -c ../temperature.txt -A 1 -n 1000000 -s 1000 )   # paths rewritten for the subdirectory only
  ls ./TI_$M/*.log || exit 1                          # each run directory must hold the single log TI
  mv ./TI_$M/*.log ./TI_logs/                         # promises (tutorial-2.md:151); an empty directory
                                                      # means the run failed - fix that before iterating
done                                                # distinct models -> distinct names, so no clobbering;
                                                    # if your own run does collide, stop and move artifacts
# -k 10 (scaling categories) and -a 0.3 (beta shape) are the only documented TI knobs and are the
# defaults anyway (../pyrate-command-reference/references/command-list.md:205-211); add them
# explicitly only to change the cost/accuracy trade of hazard 5.
ls ./TI_logs/*.log                                    # exactly three before -mL runs
python PyRateContinuous.py -mL ./TI_logs -b 100                              # one text file of marginal likelihoods; -b 100 is the value printed with this command (tutorial-2.md:155) and TI is where the docs demand "an appropriate burnin" (tutorial-2.md:153); if you cannot settle the -b unit (hazard 10) pass a fraction instead, e.g. -b 0.1 (../pyrate-bd-analysis/references/command-list.md:69,73)

# 6. diversity of the input table itself, for eyeballing the DD covariate (PyRate.py, tutorial-2.md:68,86)
python PyRate.py -d ./Canidae_1_G_se_est.txt -ltt 1 -grid_plot 0.1
```

Check `Gl`/`Gm` 95% HPDs against 0 (`references/tutorial-2.md`:115) and `L0`/`M0` as present-day baseline rates (`:115`) in the log, or in Tracer (`:117`). `-wd` (working directory) is documented for PyRate, not for PyRateContinuous — the `-wd ./TI_$M` above is an extrapolation; if it is rejected, move the logs manually (see *Not documented in this wiki*). The worked example above does the move (`mv ./*TI*.log ./TI_logs/`) rather than a `-wd`, and tags each run with `-out` (`../pyrate-command-reference/references/command-list.md`:32-33) — both are the safer route because `-mL` integrates every `.log` in the directory it is given (`references/tutorial-2.md`:153, hazard 12).

## Pitfalls

- **`-mL` does not know which logs are yours (hazard 12 — the silent one).** `python PyRateContinuous.py -mL .../path_to_my_logfiles -b 100` "will calculate the marginal likelihood for each file in the directory with extension \".log\"" (`references/tutorial-2.md`:153,`:155`): no file list, no pattern, no model-name filter, and the docs never say a non-TI log is skipped. Because steps 1-3 of a normal PyRateContinuous analysis leave parameter-estimation logs with exactly that extension next to your `Gl`/`Gm` posterior (`references/tutorial-2.md`:114-122, whose printed name is `.../Canidae_1_G_se_est_DD_0_exp.log`; `-A 1` output is likewise "a single log file", `:153`), a `-mL ./` in your working directory folds those non-TI runs into the marginal-likelihood table and you cannot tell afterwards which number belongs to which model. *Fix, before you run it:* do the TI runs in a directory that holds nothing else, or `mv` the finished TI logs into an empty directory and point `-mL` there. Both the mkdir/`mv` remedy and any `-wd`-style separation are **inferred** — no mirror documents `PyRateContinuous.py` with `-wd`, and none states the filenames this program writes.
- **Several runs in one directory overwrite each other; `-out` is the documented tag.** The corpus's only anti-overwrite device is `-out`, which "Add tag to default stem name of output files. This command is useful to avoid overwriting output files when running several instances of the same analysis" (`../pyrate-command-reference/references/command-list.md`:32-33). That is precisely the three-model `-A 1` loop, so tag each run (`-out TI_-1`, `-out TI_0`, `-out TI_1`). Two caveats, stated plainly: `-out` is printed on the *PyRate* page and never with `PyRateContinuous.py` (**inherited by inference**), and `PyRateContinuous`'s output-filename rule is **not documented** anywhere — the single printed example is `Canidae_1_G_se_est_DD_0_exp.log` (`references/tutorial-2.md`:122). List the directory after the first two runs and confirm the files are distinct before starting the third; if they are not, run the models one at a time and move each log aside immediately (see the previous bullet).

- **Do not re-derive the covariate yourself for `-DD`.** Supplying an external trajectory is a `-c` analysis and `-c` is documented as an *alternative to* the DD model, not an add-on (`references/pyratecontinuous.md`:32), so it changes which model you are fitting. That `-DD` derives the diversity trajectory internally from the `-d` table is an inference (no doc states it); that the derivation happens is implied by `-DD` taking no file in every printed example (`references/tutorial-2.md`:100-106). If you build a two-column table from the `-ltt` diversity output and hand it to `-c`, you have switched to the external-correlate model — and no doc states that the `-ltt` output file is readable by `-c`. Passing clade diversities as predictors is instead the documented **MBD** workflow (`../pyrate-diversity-dependence/references/tutorial-4.md`:73-74), not a documented PyRateContinuous one.
- **Rescaling changes the meaning of `Gl`/`Gm`.** The variable is rescaled to a range of 1 and shifted to 0 at the present by default (`references/tutorial-2.md`:136), so a correlation coefficient is per unit of *rescaled* variable, not per degree or per Myr. If you change it with `-r`, the docs give no argument form and no conversion rule — results from runs with different `-r` are not comparable.
- **`-m -1` is not *no analysis*.** It "fits a constant rate birth-death model" (`references/pyratecontinuous.md`:36) and is the null you compare against — the model-comparison ladder only makes sense with one `-m -1` run in it.
- **Replicates become extra columns, never an average.** `-tag` writes a single table in which the "columns with the origin and extinction of each species" are "given for each replicate" (`references/tutorial-2.md`:49) — so the file gets wider, it does not shrink N logs into one consensus estimate. The per-replicate values are posterior means unless you add `-resample`, which instead makes the run "sample ten times of origination and extinction and store them in the resulting text file as additional columns" (`references/tutorial-2.md`:57; means are documented at `references/pyratecontinuous.md`:14). Nothing states which column pair a downstream `-d` run reads if you omit `-j` — see *Not documented in this wiki*.
- **The log-file glob differs between docs — and inside one of them.** `references/pyratecontinuous.md`:11 says inputs come from "PyRate *_mcmc.log files", but its own directory example counts `*mcmc.log` files (`:17`), and `references/tutorial-2.md`:43 processes "each file with extension `*_mcmc.log`". Name your logs with the `_mcmc.log` suffix so all three readings match.
- **Duplicate `-b` in the docs' own plot line.** `references/tutorial-2.md`:122 passes `-b 100` *and* `-b 200` in one command, and `references/tutorial-2.md`:124 explains only the 200. Pass `-b` once.
- **`-b` is not comparable across pages — or within one (hazard 10).** PyRateContinuous's page counts samples (`references/pyratecontinuous.md`:14); the PyRate command list counts iterations in its definition (`../pyrate-command-reference/references/command-list.md`:69) and then counts samples in its own examples (`:72`, `:73`). The PyRate tutorial states the conversion outright — "`-b 200` indicates that the first 200 samples will be removed (i.e. the first 200,000 iterations, if the sampling frequency was set to 1,000)" (`../pyrate-bd-analysis/references/tutorial-1.md`:213) — i.e. samples × `-s` = iterations, which is the *samples* reading from the very program whose command list says iterations; `pyrate-bd-analysis` documents that conflict for `PyRate.py`, and it applies unchanged here. The chain you are cutting is small: `-n` and `-s` set "the number of MCMC iterations and sampling frequencies" together (`references/tutorial-2.md`:110), so a `-DD`/`-c` run in the documented `100,000`-`1,000,000` iteration range with the PyRate default `-s 1000` (`../pyrate-command-reference/references/command-list.md`:62) logs only 100-1000 samples (inference from those two lines; no mirror does this arithmetic for PyRateContinuous). A `-b` of a few hundred thousand is therefore not conservative but fatal, and a `-b` of a few hundred may be a no-op. *Inference, not a doc statement:* a fractional `-b` — "When set to a number between 0 and 1, it is interpreted as a fraction of the total number of MCMC generations" (`../pyrate-command-reference/references/command-list.md`:69) — is the only unit-independent choice, since a constant `-s` makes 10% of the generations and 10% of the samples the same cut. **Update — the fractional form is documented, not invented:** the rule is on the same line as the iteration-counting definition (`:69`) and the command list prints it as its own example, "`-b 0.10`  (the first 10% of the samples are discarded)" (`:73`), i.e. the docs' *own* worked cure for the unit ambiguity of hazard 10. What remains inferred is only (i) that `PyRateContinuous.py` accepts a fraction, and (ii) that `:73`'s "10% of the samples" and `:69`'s "fraction of the total number of MCMC generations" are the same cut — they agree only when `-s` is constant across the burn-in. Use `-b 0.1`/`-b 0.25` rather than a bare integer whenever you cannot verify the logged-sample count of the chain (compare the fractional `-b 0.25` used in a real `-ginput` line, `../pyrate-bdnn/references/tutorial-bdnn.md`:477).
- **`-ginput` is a one-way summarization step, so its `-b` is not a formality (hazard 11).** Every `-ginput` line this corpus prints carries a burn-in (`references/pyratecontinuous.md`:16-18; `references/tutorial-2.md`:29,41,47,55,60) because the table it writes holds means taken "after excluding burnin" (`references/pyratecontinuous.md`:14). With nothing excluded — the `-b 0` default documented for PyRate (`../pyrate-command-reference/references/command-list.md`:71; no default is printed for PyRateContinuous) — the pre-convergence tail is averaged into the origination and extinction times, and no later flag re-reads the log: `-DD`, `-c`, `-plot` and the `-A 1`/`-mL` comparison all condition on those numbers. Inspect the log in Tracer first (`references/tutorial-2.md`:117) and regenerate the table rather than trusting the one you already have.
- **Significant `G` is not a causal claim** and the docs' only stated criterion is the 95% HPD excluding 0 (`references/tutorial-2.md`:115); no p-value, no Bayes factor on `G` is documented.
- **Convergence guidance is quantitative but soft** (`100,000`-`1,000,000` iterations, `references/tutorial-2.md`:112) and no default `-n` for PyRateContinuous is printed; the PyRate default `-n 10000000` (`../pyrate-command-reference/references/command-list.md`:58) belongs to a program with more parameters to sample; the tutorial states the opposite for this one, "the number of parameters to be estimated is much smaller than in a standard PyRate analysis" (`references/tutorial-2.md`:112). Do not assume it.
