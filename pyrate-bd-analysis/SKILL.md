# PyRate birth-death analysis: setup, run, read the output

## Overview

A standard PyRate run on a `*_PyRate.py` occurrence file estimates three things at once: "**origination and extinction times** of each lineage", "**preservation rate** and its level of **heterogeneity**", and "**speciation and extinction rates** through time" (`references/tutorial-1.md`:163-165), where temporal rate variation is carried by rate shifts whose number and placement are estimated from the data (`references/tutorial-1.md`:167). The analysis mode is chosen with `-A`: `0` = MCMC parameter estimation with a fixed number of shifts, `1` = MCMC with thermodynamic integration (TI) for a marginal likelihood, `2` = BDMCMC jointly estimating number/placement/magnitude of shifts, `3` = MCMC with a Dirichlet Process Prior on rates within fixed time bins (`references/command-list.md`:47-54). Everything except the input file has a documented default (`references/tutorial-1.md`:176), most of which are listed inline in the command list (`references/command-list.md`:58, 62, 71, 78, 102, 168, 180, 184, 199, 207, 211, 215, 219, 223, 233, 237, 241, 245, 249, 253, 257, 261, 265, 269).

The single riskiest assumption this skill removes: **you cannot tell from the docs which algorithm runs when you omit `-A`**. The command list labels `-A 2` (BDMCMC) as the default (`references/command-list.md`:52), while the tutorial calls RJMCMC the default and says omitting the flag selects `-A 4` (`references/tutorial-1.md`:167, 174) — and `-A 4` has no entry in the command list at all (`grep -n '\-A 4' references/command-list.md` returns nothing). The Chinese twins render both sides identically (`references/command-list-cn.md`:53; `references/tutorial-1-cn.md`:168, 175), so the translation does not arbitrate. A third statement lives in another program's tutorial: `PyRateDES.py` "can be fitted with Maximum likelihood by setting the algorithm to `-A 3` instead of using the default `-A 0`" (`../pyrate-des/references/tutorial-5.md`:197) — so there, `-A 0` is called the default. Always pass `-A` explicitly. `sum.txt` is "the complete list of settings used in the analysis" (`references/tutorial-1.md`:196-197), so *by inference* it records the algorithm that actually ran — no mirror anywhere shows a `sum.txt`.

## The ten things that break a run

| # | What happens | Consequence | Wiki wording + `file:line` |
| --- | --- | --- | --- |
| 1 | Omitting `-A` leaves the algorithm undetermined by the docs | You may get BDMCMC output (`k_birth`, `k_death`, `-mProb`-able) or the different-by-default RJMCMC output while expecting the other | "`-A 2`  (default)" `references/command-list.md`:52 vs "using `-A 4` (or omitting the flag) will set the algorithm to RJMCMC" `references/tutorial-1.md`:174, on a page that calls that same algorithm the default two sentences earlier — "estimated from the data using the RJMCMC algorithm (default) or the BDMCMC algorithm" `references/tutorial-1.md`:167; "Note that the output from RJMCMC analyses is by default different" (bold in the source, which then sends you to tutorial 3) `references/tutorial-1.md`:192; and `../pyrate-rjmcmc/references/tutorial-3.md`:30 frames RJMCMC as replacing "BDMCMC (described in Silvestro et al. 2014 and available through the command `-A 2`)", spelling itself as `-A 4` at `:32`. Stated as a conflict on purpose: no page in this corpus arbitrates, so do not rely on a default — pass `-A` explicitly, and *by inference* (no mirror shows a `sum.txt`) confirm what actually ran against "the complete list of settings used in the analysis" `references/tutorial-1.md`:196-197 |
| 2 | `-b` means *iterations* in one sentence and *samples* in the next | You discard 1,000 samples (=`-s` × 1,000 iterations) or 1,000 iterations, depending on which line you believed | "Set the number of iterations to be discarded (i.e. not logged)" `references/command-list.md`:69 vs "`-b 1000`  (first 1,000 samples are discarded)" `references/command-list.md`:72 and "`-b 200` indicates that the first 200 samples will be removed (i.e. the first 200,000 iterations, if the sampling frequency was set to 1,000)" `references/tutorial-1.md`:213; a third page of the same wiki counts samples when it reads a PyRate log — "the number of samples excluded is set with the command `-b`" `../pyrate-continuous-covariates/references/pyratecontinuous.md`:14, example "after excluding the first 100 samples as burnin" `:16`. This is a conflict, not a choice: `:69` does attach the samples sense to summarizing ("This command is also used to exclude burnin samples when summarizing MCMC results"), but **no page ever says which sense its own Examples lines carry**, so neither reading is adopted here — convert with `-s` and count the rows of the log you actually got (**inference**, and the one check that settles it) |
| 3 | Burnin is not removed by default (`-b 0`) | Every summary/plot computed without `-b` includes pre-convergence samples; the plot page even states a different default | "`-b 0`  (default; all samples are logged)" `references/command-list.md`:71; the burnin number "should be determined after inspecting the log files, e.g. using Tracer" `references/tutorial-1.md`:229; but for `-plot` the burnin is "(by default set to 1)" and for `-mProb` "(by default set to 0)" — `../pyrate-summarize-results/references/summarize-results.md`:40 and :64 |
| 4 | `-nT 0` silently rewrites the preservation model | Times of speciation/extinction stop being estimated *and* NHPP/HPP/TPP is replaced by HPP — a model change from a tuning flag | "If set to 0, speciation/extinction times are set equal to first/last appearances and the preservation model is automatically set to HPP" `references/command-list.md`:240 |
| 5 | `-d` (origin/extinction table input) silently turns estimation off | Preservation rates and times of speciation/extinction are not estimated; only BD parameters are sampled. What the `PP_lik`/`q_rate` columns of `mcmc.log` then hold is never stated | "This option automatically sets `-fixSE = null`"; the effect is that "the estimation of preservation rates and times of speciation/extinction are switched off" `references/command-list.md`:18 |
| 6 | `-fixSE` silently drops the preservation likelihood | Same trap as `-d`, easy to leave on when reusing a command line from a previous analysis | "without  estimating them and without calculating the likelihood of the  preservation process (NHPP or HPP), but only sampling the parameters  of the birth-death" `references/command-list.md`:105 |
| 7 | `-fixShift` silently swaps the rate priors | Gamma priors on speciation/extinction become half-Cauchy with `-cauchy 0 0` (scale inferred from data) — priors in `sum.txt` change without you touching a prior flag | "This will automatically switch the priors on speciation and extinction rates into half-Cauchy distributions" `references/command-list.md`:124; the same line makes `-cauchy 0 0` the default when `-fixShift` is used `references/command-list.md`:175 |
| 8 | Only one age replicate is analysed (`-j 1` default) | Dating uncertainty in the fossil record is ignored; the tutorial's own input file holds 10 replicates | "`-j 1`  (default; the first data set from the input file is analyzed)" `references/command-list.md`:30; "**Ideally, we should analyze multiple randomized replicates and combine the results to incorporate dating uncertainties**" `references/tutorial-1.md`:178 |
| 9 | Two runs of the same data write the same file names | The second run overwrites the first unless `-out` tags the stem or `-wd` redirects the directory | "This command is useful to avoid overwriting output files when running several instances of the same analysis" `references/command-list.md`:33 |
| 10 | `-A 3` is experimental | Do not build an analysis on it yet — it carries the only `Warning:` in the `-A` block and no example, no output description | "Warning: this function is currently still being tested." `references/command-list.md`:54; the CN twin carries the same warning (警告：该功能目前仍处于测试阶段) at `references/command-list-cn.md`:55, and it is the only `-A` entry to do so |

Runner-up hazards: `-singleton 1/2/-1` removes taxa *before* the run, changing the data set behind the numbers (`references/command-list.md`:38-42); `-thread 0 0` is the default and runs the likelihood sequentially (`references/command-list.md`:78); ESS must be computed per replicate and **not** from a combined log (`references/tutorial-1.md`:206); `python PyRate.py` requires Python 2.6-2.7 — "Please note that Python 3.x is currently not supported" — the sentence continues in the same bold span with where to get 2.7.x (`../pyrate/references/home.md`:69), and `-plot` shells out to `Rscript` (`../pyrate/references/home.md`:84).

## The BDMCMC rate-shift analysis end to end (`-A 2`, the Canis route)

The tutorial's own Canis walk-through, every command line in printed order, is a fixture: `../assets/files/bd-canis-run-commands.txt`. Step map:

| 2. Load the R utilities | `source(".../PyRate-master/pyrate_utilities.r")` | :31 |
| 3. Declare extant species (all others "will be considered as extinct") | `extant_dogs = c("Canis rufus",…)` | :33-34 |

| 7. Preservation model + replicate | `python PyRate.py .../Canis_pbdb_data_PyRate.py -A 2 -mHPP -mG -j 1` | :180 |
| 8. Run length | `python PyRate.py .../Canis_pbdb_data_PyRate.py -mG -n 20000000 -s 5000` | :186 |
| 9. Read the logs | Tracer for ESS/convergence; `-mProb` for shift-number probabilities | :205-213 |

Two facts the tutorial states about step 6-7 that are easy to lose: `extract.ages`/`extract.ages.pbdb` write **two** files (`*_SpeciesList.txt` and `*_PyRate.py`, `references/tutorial-1.md`:40), and the `replicates` option "resamples the ages of each fossil occurrence from the respective temporal range", with `replicates=10` saving ten data sets in one input file (`references/tutorial-1.md`:38). The parsing function "does not check for synonyms, typos, etc." (`references/tutorial-1.md`:38) — `-check_names` looks for "inconsistent spelling in species names" (`references/tutorial-1.md`:94) and "does NOT check for synonyms!" (`references/tutorial-1.md`:101). Input-file formatting itself belongs to `pyrate-input-file`.

### Which preservation model? Test it before you copy `-mHPP`

| Step | What the docs say | Mirror line |
| --- | --- | --- |
| Write nothing → you get NHPP | `-mHPP` exists to *replace* a default: it uses a homogeneous Poisson process "instead of  non-homogeneous Poisson process (NHPP)", and the same entry closes "Note that the NHPP is  used unless differently specified." | `references/command-list.md`:88 |
| Test the three candidates before committing | a maximum likelihood test across them "is available to assess which of NHPP, HPP, or TPP is best supported by the data"; it takes the input file, the file with the times of rate shift for the TPP model, and `-PPmodeltest` | `references/tutorial-1.md`:154, command as printed at `references/tutorial-1.md`:156 |
| Then add Gamma to the winner | Gamma is not part of that test, and the page recommends adding it afterwards: "we recommend to add it to the best model among NHPP, HPP, or TPP as selected by the model testing" | `references/tutorial-1.md`:158 |

So every `-mHPP` in this skill's worked commands (step 7 of the table above; the preservation-model examples at `references/tutorial-1.md`:144-146, which pair it with `-mG`) is an **explicit model choice, not an inherited default** — passing it switches the preservation process away from NHPP, exactly the switch hazard 4 says `-nT 0` makes silently. Run `-PPmodeltest` first and carry the winner into the analysis, or omit `-mHPP` and state that you left the documented NHPP default in place. Note that the tutorial never says such a test was run on the *Canis* data set behind its own command lines (**not documented** — the printed commands simply carry the flag). `-PPmodeltest` itself, NHPP/HPP/TPP and `-ncat` are owned by `pyrate-preservation-models`; this section only stops a copied flag from silently changing your model.

## Three different "rate shifts" analyses — do not confuse them

Verbatim source blocks for all three: `../assets/files/bd-shift-workflows.txt`.

| Goal | Command line the docs print | What changes in the model |
| --- | --- | --- |
| Number and placement of shifts **estimated** (BDMCMC) | `python PyRate.py .../Canis_pbdb_data_PyRate.py -A 2` (`references/tutorial-1.md`:172) | `k_birth`, `k_death` are sampled parameters; `-M`/`-B`/`-T`/`-S` tune the exploration (`references/command-list.md`:214-226) |
| Speciation and extinction rates **within fixed time bins** — shift number and ages fixed a priori | `python PyRate.py .../Canis_pbdb_data_PyRate.py -fixShift .../epochs.txt` (`references/tutorial-1.md`:252) | "the number and temporal placement of the rate shifts is fixed and set identical for both speciation and extinction", priors → half-Cauchy with a hyper-prior on the scale (`references/command-list.md`:124; `references/tutorial-1.md`:249); the log loses `k_birth`/`k_death` and gains `lambda_*`, `mu_*`, `hypL`, `hypM` (`references/tutorial-1.md`:257) |
| Shifts fixed **at the data boundaries** while the algorithm searches **between** them | `python PyRate.py <data_set> -A 4 -edgeShift 18 2` (`references/tutorial-1.md`:267); max-age only: `-edgeShift 18 0` (:272); min-age only: `-edgeShift inf 0` (:276) | truncation-driven edge shifts are absorbed at the boundary and "the algorithm will only search for shifts within this time range" (`references/tutorial-1.md`:269); summarise only inside the window, e.g. `plotRJ` with `-root_plot` and `-min_age_plot` (`references/tutorial-1.md`:278) |
| A **fixed, user-specified number** of rates, positions free | `-mL 2` / `-mM 3` with `-A 0` or `-A 1`; `-mC` to force the same time frames for both rates (`references/command-list.md`:112, 116, 120) | "In BDMCMC analyses (`-A 2`) this command is only used to set the number of starting rates" (`references/command-list.md`:112) — `-mL`/`-mM` do **not** fix the model under `-A 2` |

The boundary case exists because "Sometimes fossil data sets are truncated by max and min boundaries" and "This can cause apparent rate shifts at the edges of the time range, which reflect the sampling bias" (`references/tutorial-1.md`:265). Note that `-edgeShift` appears only in the tutorial: `grep -n edgeShift references/command-list.md` finds nothing, so its value grammar is known only from the three example lines; by inference from the two one-sided examples — `-edgeShift 18 0` (`references/tutorial-1.md`:272), which the page introduces as setting "only a max age boundary shift" (`references/tutorial-1.md`:270), and `-edgeShift inf 0` (`:276`), introduced as "a min age boundary shift" (`:274`) — a `0` in a slot means no shift at that edge and `inf` means no boundary there, but the docs never say so in those words.

## Priors and hyperpriors relevant to a plain BD run

| Flag | Prior it sets | Documented default | Caveat in the docs |
| --- | --- | --- | --- |
| `-N` | number of extant species, used for the hyperprior on speciation/extinction rates conditioned on present diversity (Kubo & Iwasa 1995; eqs. 12-15 of Silvestro et al. 2014) (`references/command-list.md`:162-163) | "`-N -1` or if not specified, a gamma prior will be used instead" (`:163`) | the gamma fallback takes its shape/scale from `-pL`/`-pM`. It is **the gamma option, not `-N`**, that the docs recommend for "clades that have gone extinct or when the current diversity is doubtful" — "The latter option" in `:163` refers to the gamma prior just described (`:163`) |
| `-pL` | "Shape and scale parameters of the gamma distributed prior on the speciation rate" (`references/command-list.md`:166-167) | `-pL 1.1 1.1` (`:167`) | "used only if the number of extant taxa is not specified (i.e. `-N -1`)" (`:167`) |
| `-pM` | same for the extinction rate (`references/command-list.md`:170-171) | printed as `-pL 1.1 1.1` on the `-pM` page (`:172`) — the docs' own copy/paste error, kept in the CN twin (`references/command-list-cn.md`:172); treat the value `1.1 1.1` as the default and the flag name as a typo | same `-N -1` condition (`:171`) |
| `-pP` | gamma prior on the preservation rate (`references/command-list.md`:178-180) | `-pP 1.5 1` (`:180`) **but** the tutorial says "a single gamma distribution with shape = 1.5 and rate = 1.5" (`references/tutorial-1.md`:134) | conflict; and the two pages name the second slot differently — the command list says "Shape and scale parameters" (`references/command-list.md`:179) where the tutorial says "shape = 1.5 and rate = 1.5" (`references/tutorial-1.md`:134) |
| `-pS` | "Shape parameter of the Dirichlet prior on the length of the time frames relative to the total time span of the data set"; `-pS 1` = uniform, big values favour equal-sized frames (`references/command-list.md`:182-183) | `-pS 2.5` (`:184`) | the docs never say which `-A` modes use it |
| `-cauchy` | "This command sets half-Cauchy distributions as hyper priors on speciation and extinction rates" (`references/command-list.md`:174-175) | "Default `-cauchy -1 -1` is applied when different priors are used (e.g. Gamma)"; `-cauchy 0 0` is the default when `-fixShift` is used and then "the scale parameters will" / "be inferred form the data" (typo `form` in the original; the sentence wraps across `:175-176`); `-cauchy x y` with x, y > 0 sets the scales to x (speciation) and y (extinction) (`:175-176`) | the only *hyper*prior page that names a condition on another flag (`-fixShift`); it does not say what `-cauchy` does under `-A 2` |

Outside this skill's scope but on the same wiki page section: `-pC` (Normal(0, `-pC`) prior on the Covar correlation parameters, default `-pC 1`, `references/command-list.md`:186-188) belongs to `pyrate-trait-age-models`.

Times of origination and extinction are parameters, not priors: they are estimated per taxon and logged as `*_TS` / `*_TE` (`references/tutorial-1.md`:199), they can be frozen from a previous run with `-fixSE` (`references/command-list.md`:104-106) or supplied directly with `-d` (`:17-20`), and their update window is `-tT` with at most `-nT` times updated at once (`:235-241`).

## What a run writes: reconciling the tutorial with the wiki

The tutorial's "Output files" section (`references/tutorial-1.md`:191-201) and the wiki's "Description of the output files" section (`../pyrate-summarize-results/references/summarize-results.md`:12-30) describe the same three files; the wiki adds the mode conditions the tutorial omits, and the tutorial adds columns the wiki omits.

## Combining the logs across replicates: `-combLog`, `-plotQ` and the `-tag`/`-b` they take

These two commands are printed **only** in Tutorial 1, i.e. in this skill's mirrors — `../pyrate-summarize-results/references/summarize-results.md` has no entry for either (`grep -n 'combLog\|plotQ' ../pyrate-summarize-results/references/summarize-results.md` returns nothing), so `pyrate-summarize-results` routes them here. What they do and what they consume; the R-script/PDF internals stay with that sibling.

| Command | Line as printed | What the page says |
| --- | --- | --- |
| `-combLog` | `PyRate.py -combLog path_to_your_log_files -tag mcmc -b 100` (`references/tutorial-1.md`:227) | combines "log files from different replicates into one" (`references/tutorial-1.md`:225); the rest of the cell quotes line 229: `path_to_your_log_files` is "the directory where the log files are"; `-tag mcmc` "sets PyRate to combine all files that contain _mcmc.log_ in the file name"; `-b 100` means that "the first 100 samples from each log file should be excluded as burnin", a number that "should be determined after inspecting the log files, e.g. using Tracer" (`:229`) |
| `-plot` over a directory | `PyRate.py -plot path_to_your_log_files -tag Canis_pbdb -b 100` (`references/tutorial-1.md`:233) | "combine all the _marginal\_rates.log_ files which include `Canis_pbdb` in the file name and combine the results in a single plot." — "Different tags can be used to determine which files are to be combined." (`:235`; the two sentences are separated by a zero-width space in the source, so they are quoted separately here) |
| `-plotQ` | `PyRate.py -plotQ .../Canis_pbdb_data_mcmc.log -qShift epochs.txt -b 100` (`references/tutorial-1.md`:241) | plots the TPP preservation rates: `-plotQ` is "followed by the `mcmc.log` file (including path to file)" and "the file with the times of rate shift (e.g. `PyRate-master/example_files/epochs_q.txt`) should be provided as well" (`:239`, `:243`) |

Two traps in those lines. (1) Combining logs is for plotting/speed only: the ESS "should be computed from the log files of each replicate" and not from a combined log file — the page words it as a hyperlink (`references/tutorial-1.md`:206) — so check convergence *before* `-combLog`, never after. (2) The `-plotQ` example passes `-qShift epochs.txt` (`:241`) while the sentence right below it names `epochs_q.txt` (`:243`), and `epochs.txt` is elsewhere the `-fixShift` (rate-shift) file (`references/command-list.md`:124-125). The corpus never resolves which file `-plotQ` wants; pass the same TPP delimiter file the run itself used (`-qShift`, `references/command-list.md`:92-93) and treat the `epochs.txt` in the example as a typo.

## Worked example

Run from this skill directory. `../assets/files/bd-canis-run-commands.txt` is the tutorial's Canis run in printed order; the commands below are those same printed lines (`references/tutorial-1.md`:45, 172, 180, 186, 211, 218, 227, 233, 252, 267) with `.../` replaced by shell variables — the `.../` notation is the docs' own ("the full path of a file is here indicated as `.../` for simplicity", `references/tutorial-1.md`:31) — plus two `-out` tags that the printed lines do not carry (`-out` itself is documented at `references/command-list.md`:32-35); steps 2-3 also add the two pre-run checks named below the block (`-singleton 1 -data_info`, `-PPmodeltest`).

```sh
# Anchor: the ../assets/... and ../<sibling>/... paths below are written relative to the folder
# that holds this SKILL.md, so make that folder the working directory. After install it is
# $HOME/.qoder/skills/pyrate-bd-analysis and the shared library sits beside it at
# $HOME/.qoder/skills/assets/ (see pyrate-installation and the suite README). If you kept the
# unpacked bundle instead, override the variable - nothing else below needs changing:
#     SKILL=/your/path/to/PyRate-skills/pyrate-bd-analysis
SKILL="${SKILL:-$HOME/.qoder/skills/pyrate-bd-analysis}"
cd "$SKILL"        # step 0 prints "No such file or directory" if this is not the skill folder

# 0. what the copy-pasteable run actually contains, and that the modes fixture is on disk
ls -l ../assets/files/bd-canis-run-commands.txt ../assets/files/bd-analysis-modes-A.txt ../assets/files/bd-shift-workflows.txt
grep -c '^[^#]' ../assets/files/bd-canis-run-commands.txt          # 27 command lines the tutorial prints
grep -n 'Warning' ../assets/files/bd-analysis-modes-A.txt          # the -A 3 warning

# 1. environment: PyRate runs under Python 2.6-2.7 only (../pyrate/references/home.md:69)
#    and pyrate_lib must sit next to PyRate.py — see pyrate-installation
PYRATE=/path/to/PyRate-master          # directory holding PyRate.py
IN="$PYRATE/Canis_pbdb_data_PyRate.py" # generated by extract.ages.pbdb(..., replicates=10)
cd "$PYRATE"

# 2. check the input file (tutorial-1.md:45)
python PyRate.py "$IN" -data_info
python PyRate.py "$IN" -singleton 1 -data_info  # the documented pre-run exclusion switch, checked with -data_info
#   (`references/command-list.md`:37-42): -data_info then prints "number of species excluded as singletons"
#   alongside the extant-taxon, occurrence and time-span counts (`../pyrate-summarize-results/references/summarize-results.md`:10),
#   and the `-singleton` page itself says the counts are available in that combination (`references/command-list.md`:38).
#   Do this BEFORE the long run on a genus-level / singleton-heavy table: excluding taxa changes the data set.
#   Also clear the two input-file gates here (see Pitfalls): no blank cell in the four mandatory columns
#   (`../pyrate-input-file/references/preparing-input-file.md`:14) and no species listed with both statuses.

# 3. the BDMCMC rate-shift analysis, as the tutorial sets it up (tutorial-1.md:172, 180, 186)
python PyRate.py "$IN" -qShift "$PYRATE/example_files/epochs_q.txt" -PPmodeltest  # test first: assesses
#   "which of NHPP, HPP, or TPP is best supported by the data" (`references/tutorial-1.md`:154, command as
#   printed `references/tutorial-1.md`:156), then add `-mG` to the winner (`references/tutorial-1.md`:158)
python PyRate.py "$IN" -A 2
python PyRate.py "$IN" -A 2 -mHPP -mG -j 1      # -mHPP overrides the documented default - see next line
#   "Note that the NHPP is  used unless differently specified." (`references/command-list.md`:88): omit the
#   flag to stay on NHPP, or run the test above and carry its winner into the analysis
python PyRate.py "$IN" -mG -n 20000000 -s 5000          # note: no -A on this printed line!

# 4. read what actually ran, then the logs (tutorial-1.md:194-201, 205)
ls "$(dirname "$IN")/pyrate_mcmc_logs"                   # sum.txt  mcmc.log  marginal_rates.log
less pyrate_mcmc_logs/sum.txt     # "the complete list of settings used in the analysis" (:196-197);
#   the corpus never shows a sum.txt, so do not grep it for a key name you expect - read it
# open mcmc.log in Tracer for ESS/burnin; compute ESS per replicate, never on a combined log (tutorial-1.md:206)

# 5. shift-number probabilities and the RTT plot (tutorial-1.md:211, 218)
#    NB the docs write these paths as ".../Canis_pbdb_data_mcmc.log"; joining that stem to the
#    pyrate_mcmc_logs folder is an inference - the two are never combined in one printed path.
python PyRate.py -mProb "$(dirname "$IN")/pyrate_mcmc_logs/Canis_pbdb_data_mcmc.log" -b 200
python PyRate.py -plot  "$(dirname "$IN")/pyrate_mcmc_logs/Canis_pbdb_data_marginal_rates.log" -b 200

# 6. the DIFFERENT analysis: rates within fixed time bins (tutorial-1.md:252)
python PyRate.py "$IN" -fixShift "$PYRATE/example_files/epochs.txt" -out fixShift

# 7. and shifts pinned to the truncated edges while searching between them (tutorial-1.md:267)
python PyRate.py "$IN" -A 4 -edgeShift 18 2 -out edge   # -A 4 = RJMCMC -> pyrate-rjmcmc owns the output

# 8. combine the per-replicate logs, then plot all replicates as one RTT (tutorial-1.md:227, 233)
PyRate.py -combLog "$(dirname "$IN")/pyrate_mcmc_logs" -tag mcmc -b 100
PyRate.py -plot "$(dirname "$IN")/pyrate_mcmc_logs" -tag Canis_pbdb -b 100
```

Steps 2-8 reproduce the lines the tutorial prints (`references/tutorial-1.md`:45, 172, 180, 186, 211, 218, 227, 233, 252, 267) with `.../` replaced by shell variables; steps 6-7 additionally add an `-out` tag, which the printed lines do not carry (`-out` itself is documented at `references/command-list.md`:32-35). Step 3's third command is copied from the tutorial verbatim, and it carries no `-A`: by `references/command-list.md`:52 that is the default anyway, by `references/tutorial-1.md`:174 omitting the flag means RJMCMC. That is hazard 1 in the wild — add `-A` explicitly. Everything about the R script and PDF that `-plot` shells out to is owned by `pyrate-summarize-results`.

Two commands in steps 2-3 are **additions, not reproductions** of tutorial lines: `-singleton 1 -data_info` (the combination is documented on the `-singleton` page, `references/command-list.md`:38, but the tutorial never prints it) and the `-PPmodeltest` call (its own printed line is `python PyRate.py .../Canis_pbdb_data_PyRate.py -qShift .../epochs_q.txt -PPmodeltest`, `references/tutorial-1.md`:156 — the docs print `.../epochs_q.txt`, so the `$PYRATE/example_files/` path here follows this skill's existing step-6 convention, not a printed line). Both are run *before* the analysis and change what it assumes, which is why they sit ahead of step 3's runs.

## Pitfalls

- **`-A 2` changes the meaning of `-mL`/`-mM`.** Under `-A 0`/`-A 1` they fix the number of rates; under `-A 2` they are "only used to set the number of starting rates" (`references/command-list.md`:112, 116). Reusing one command line across modes silently changes the model.
- **`-b` is not comparable across flags.** Run-time `-b` is described in iterations (`references/command-list.md`:69) but used as samples in every example (`:72`, `references/tutorial-1.md`:213, 229). Convert with `-s`: 200 samples at `-s 1000` = 200,000 iterations (`references/tutorial-1.md`:213).
- **`-fS` cross-references `-fixSE` for fixed shift times.** "The value will be automatically set to 0 when no rate shifts are being sampled or if the times of shifts are fixed" — the page then names `-fixSE` as that command (`references/command-list.md`:256; the CN twin resolves the same cross-reference to `-fixSE` too, `references/command-list-cn.md`:255) — yet `-fixSE` fixes taxon speciation/extinction times (`:105`) and `-fixShift` fixes shift times (`:123`). Do not assume which one the code checks; the two pages cannot both be right and neither is corrected by the translation.
- **`-pM`'s printed example is `-pL`.** `references/command-list.md`:172 reads ``Example: `-pL 1.1 1.1` (default)`` under the `-pM` heading; take the numbers, not the flag name.
- **The preservation-prior default is stated twice, differently.** `-pP 1.5 1` (`references/command-list.md`:180) vs shape 1.5 / rate 1.5 (`references/tutorial-1.md`:134). The docs also call the second slot "scale" (`references/command-list.md`:179) and "rate" (`references/tutorial-1.md`:134) — and the CN twin preserves both words (`references/command-list-cn.md`:178 尺度参数 vs `references/tutorial-1-cn.md`:135 速率参数), so no arbitration is possible from this corpus.
- **The `-mC` description is truncated in the source.** "This command is only used in birth-death models with at least one rate shift (e.g. with `-mL 2` and `-mM 2`) and" (`references/command-list.md`:120) — the sentence has no ending in English *or* Chinese (`references/command-list-cn.md`:120). Do not guess the missing condition.
- **Typos are in the source, not in your copy.** `larwger` (= larger) at `references/tutorial-1.md`:38, `PyRte` and `yRate's` (`references/tutorial-1.md`:94), "be inferred form the data" (`references/command-list.md`:176), "can be use to compare" (`:49`), "the estimate number of rate shifts" (`references/tutorial-1.md`:257), and a stray literal tab inside two sentences of the `-A` block (`references/command-list.md`:49, 51). The mirrors keep them verbatim.
- **Log-file names embed the data-set stem.** The examples read `Canis_pbdb_data_mcmc.log`, i.e. stem + `_mcmc.log`, while `-fixSE`'s own example is written `Ursidae.mcmc.log` with a **dot** (`references/command-list.md`:106). Pass the file your run actually wrote (`ls pyrate_mcmc_logs`) rather than a pattern from the docs.
- **Running straight from a table you produced? Pass the two input-file gates first.** Any time the `*_PyRate.py` (or the `-d` origin/extinction table) comes from a script, a spreadsheet, or a merge of previous-run output rather than from the tutorial's R call, check before the long run: (1) **no blank cell in the four mandatory columns** — "At present, PyRate can not deal with missing information in these four columns, so make sure that you remove these entries beforehand" (`../pyrate-input-file/references/preparing-input-file.md`:14); upstream the stop prints a message naming `species names, status or ages`, but that string is **not in this corpus** — it is recorded as an engineering check in the `pyrate-input-file` skill's non-mirror "Verified outside this corpus" block, so cite it as behaviour, not as documentation. (2) **no species listed as both `extant` and `extinct`** — the table holds one `Status` per row, valued "extant" or "extinct" (`../pyrate-input-file/references/preparing-input-file.md`:14), while the R route sets it from a vector of extant names and everything else is "considered as extinct" (`references/tutorial-1.md`:33), so hand-edits, re-assignments, or joining a by-genus list to an occurrence list are where the two mix. The upstream stop prints `at least one species is listed as both extinct and extant`; again **not in this corpus** (same non-mirror block). Both conditions are visible without running anything: `-data_info` prints species counts, extant taxa, occurrences and the observed time span (`../pyrate-summarize-results/references/summarize-results.md`:10) — see step 2 of the worked example.
- **`-singleton` excludes taxa before the analysis, so it changes the data behind your numbers.** `1` drops single-occurrence taxa, `2` taxa with ≤2 occurrences, `-1` all extant taxa (`references/command-list.md`:37-42); it is the only documented pre-run exclusion switch, and the excluded/remaining counts are printed on screen and also reported by `-data_info` (`references/command-list.md`:38; `../pyrate-summarize-results/references/summarize-results.md`:10). Nothing in the corpus says when to use it or what it costs (**not documented**), so record the flag and the printed counts in your methods.
- **A plain run is long.** Defaults are 10,000,000 generations sampled every 1,000 (`references/command-list.md`:58, 62) — budget for it, or shorten deliberately and then justify convergence in Tracer (`references/tutorial-1.md`:184, 205).
